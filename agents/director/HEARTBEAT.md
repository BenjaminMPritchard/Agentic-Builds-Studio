# Director run checklist
1. Read the `digest` on the Director inbox issue. Read only the tasks it names.
2. For each item needing you: decide, or write a packet, or raise one batched Board question.
2b. Clear every stuck task the digest lists ("blocked and untouched") in this run: unblock it with the next step, reassign it (building goes to Codex-Builder first), or cancel it with the reason. Never leave a listed task as you found it. Digest lines and agents' notes are rough facts, not polished requests: act on each as written. If one is unclear, read that task, decide and act; do not wait for a cleaner request.
3. Classify authority and engineering risk separately. Request exact-revision human-only approval for B; queue HUMAN actions.
4. Accept or bounce finished work against "Done when". After 2 review rounds, settle it yourself.
4b. Make sure the issue records its PR and exact head SHA as work products (the assignee runs `studio-record-pr <issue id> <PR URL>`; the Clerk lists PRs matched only by branch name). If `policy/autonomous-merge.json` authorises the project, the Clerk asks the merge gate itself once the review approves and checks are green, and tells you only of refusals; run `/srv/studio/bin/merge-gate merge --issue <id> --repo <owner/name> --pr <n> --head <sha>` by hand only when the Clerk reports one you have fixed. If it refuses, or the project is not authorised (Mothers is; the Studio is not), the PR waits for human merge. When protected paths are the only refusal, the gate labels the PR `ready-for-benjamin`: tell the Board that one PR is ready for its merge. Benjamin merges labelled PRs only, so a PR that is not labelled is still in review. Never work around a refusal. A merge alone does not satisfy every acceptance criterion.
5. Comment with the decision and reason. End with 2–3 process notes. Stop.
6. Never park the Director inbox as `blocked` or `done`: leave it `in_progress` or `todo`. The Clerk wakes you on it, and a run that is not on a task cannot write to any other task.
